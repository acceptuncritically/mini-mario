# 迷你马里奥（mini-mario）需求规范文档

- 版本：1.0
- 状态：已与用户确认（3 轮需求讨论）
- 关联文档：[测试用例文档 TEST_CASES.md](./TEST_CASES.md)

---

## 1. 项目概述

**mini-mario** 是一款运行在浏览器中的 2D 横向卷轴平台跳跃游戏，玩法类似经典游戏《超级马里奥》：
玩家控制角色在平台上奔跑、跳跃，躲避并踩踏敌人，收集金币，抵达关卡终点的旗帜进入下一关，
通关全部关卡后显示胜利画面。

### 1.1 已确认的需求决策

| 决策项 | 结论 |
| --- | --- |
| 技术栈 | Web：HTML5 Canvas + 原生 JavaScript（ES Module） |
| 玩法范围 | 标准版：移动 + 跳跃 + 平台 + 巡逻敌人 + 金币 + 生命值 |
| 画面风格 | 简单几何图形占位（彩色矩形/圆形，无美术素材） |
| 关卡数量 | 3 个关卡，横向卷轴，镜头跟随玩家 |
| 操作方式 | 键盘（方向键 + 空格）+ 触屏虚拟按钮 |
| 敌人设计 | 巡逻型敌人，可被踩死；侧面接触受伤 |
| 伤害规则 | 3 条命；受伤后有 1.5 秒无敌闪烁；掉落深渊扣 1 条命并重生 |
| 计分规则 | 金币 +100、踩敌 +100、通关奖励（剩余生命 × 200） |
| 关卡流程 | 终点旗帜 → 下一关；第 3 关通关 → 胜利画面；死亡从当前关卡起点重生 |
| 镜头 | 横向卷轴，镜头跟随玩家并限制在关卡边界内 |
| 触屏布局 | 左下角「◀ ▶」方向按钮 + 右下角「跳跃」按钮，仅触屏设备显示 |
| 音效 | 无（后续可扩展） |
| 测试 | Vitest 测试核心逻辑（物理/碰撞/计分/生命/关卡切换/镜头）；渲染层不测 |
| 交付物 | 项目文件夹 `mini-mario/`，包含规范文档、测试用例文档、源码、测试，全部可运行 |

### 1.2 范围与非目标

**范围内**：上述全部玩法；单机单人；桌面浏览器与移动端浏览器均可运行。

**非目标（本版本不做）**：
- 美术素材、动画精灵图（用几何图形占位）
- 音效与音乐
- 道具（变大蘑菇等）、连击计分、更多敌人类型、Boss
- 关卡编辑、存档/排行榜、本地持久化
- 游戏手柄支持

## 2. 术语定义

| 术语 | 含义 |
| --- | --- |
| Tile（格子） | 关卡地图的基本单位，32×32 像素 |
| 实体 | 玩家、敌人、金币、旗帜等游戏对象 |
| 固态格子 | 玩家与敌人发生碰撞的 Tile（地面、平台、墙） |
| 无敌时间 | 玩家受伤后短暂不受伤害的时间段（1.5 秒），期间角色闪烁 |
| 深渊 | 关卡中无地面支撑、掉落即死亡的区域 |
| HUD | 界面上方的分数与生命显示 |

### 3.1 技术选型

| 组件 | 选型 |

### 3.3 分层原则

- **core 层**：纯数据 + 纯函数，不引用 `window`/`document`/`canvas`，全部逻辑可单元测试。
- **game 层**：负责 DOM、Canvas、输入事件与游戏循环，负责把 core 层装配成可玩的游戏。
- **时间步长**：固定逻辑帧 `dt = 1/60 s`，渲染帧与逻辑帧解耦（累积时间、逻辑帧追赶）。

## 4. 全局常量（constants.js）

所有数值常量集中定义，测试与实现必须引用同一份常量：

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `TILE_SIZE` | 32 px | 格子边长 |
| `VIEW_WIDTH` | 960 px | 逻辑视口宽 |
| `VIEW_HEIGHT` | 544 px | 逻辑视口高（= 17 行格子） |
| `LEVEL_ROWS` | 17 | 关卡行数 |
| `LEVEL_WIDTH_TILES` | 100 | 关卡列数（约 3.3 屏宽） |
| `GRAVITY` | 1600 px/s² | 重力加速度 |
| `MAX_FALL_SPEED` | 950 px/s | 最大下落速度 |
| `MOVE_SPEED` | 260 px/s | 水平移动速度 |
| `JUMP_VELOCITY` | -640 px/s | 起跳初速度（y 轴向上为负） |
| `STOMP_BOUNCE` | -380 px/s | 踩死敌人后的反弹速度 |
| `PLAYER_WIDTH` | 28 px | 玩家碰撞盒宽 |
| `PLAYER_HEIGHT` | 36 px | 玩家碰撞盒高 |
| `ENEMY_SIZE` | 32 px | 敌人碰撞盒边长 |
| `ENEMY_SPEED` | 60 px/s | 敌人巡逻速度 |
| `ENEMY_STOMP_THRESHOLD` | 12 px | 踩踏判定阈值 |
| `COIN_SIZE` | 24 px | 金币碰撞盒边长（位于格子中心） |
| `INVINCIBLE_TIME` | 1.5 s | 受伤无敌时长 |
| `START_LIVES` | 3 | 初始生命数 |
| `COIN_SCORE` | 100 | 金币得分 |
| `STOMP_SCORE` | 100 | 踩敌得分 |
| `LIFE_BONUS` | 200 | 通关时每条剩余生命的奖励分 |
| `LEVEL_CLEAR_PAUSE` | 1.5 s | 通关画面停留时长 |
| `PIT_DEATH_MARGIN` | 64 px | 玩家顶部低于关卡底边该值时判定坠落死亡 |
| `FIXED_DT` | 1/60 s | 固定逻辑帧长 |

坐标约定：**y 轴向下为正**；实体坐标 `(x, y)` 表示碰撞盒左上角；像素坐标原点在关卡左上角。

## 5. 核心玩法规范

### 5.1 物理（physics.js）

1. 重力：每个逻辑帧 `vy += GRAVITY * dt`，`vy` 不超过 `MAX_FALL_SPEED`。
2. 水平速度：由输入直接设定（无加速度、无惯性），大小为 `MOVE_SPEED`，空中与地面相同。
3. AABB 相交判定：两个矩形重叠（含边界接触不算相交）即视为相交。
4. 每帧运动顺序：**先水平移动并做碰撞响应，再垂直移动并做碰撞响应**（分轴处理，避免穿墙）。

### 5.2 碰撞与响应（collision.js）

1. 固态格子：关卡 Tile 中标记为实心的格子。玩家与敌人的碰撞盒均与固态格子做 AABB 检测。
2. 水平响应：向右移动撞到格子时，`x = 格子左边界 - 碰撞盒宽`；向左同理贴齐。
3. 垂直响应：下落撞到格子顶部时，`y = 格子顶部 - 碰撞盒高`，`vy = 0`，并置 `grounded = true`；
   上升顶到格子底部时，`y = 格子底部`，`vy = 0`（顶头失速）。
4. 接地状态：只有当本帧垂直下落过程中实际踩到固态格子顶部时才为 `grounded`；
   每帧开始时重置为 `false`（空中无法起跳）。
5. 金币拾取：玩家碰撞盒与金币碰撞盒 AABB 相交即拾取，拾取后金币从关卡中移除。
6. 旗帜：玩家碰撞盒与旗帜区域相交即触发通关。

### 5.3 踩踏判定（敌人）

当玩家与敌人碰撞盒相交时：

1. 若 `player.vy > 0`（正在下落）**且** 玩家底部 `≤ 敌人顶部 + ENEMY_STOMP_THRESHOLD`（12px）→ 判定为**踩踏**：
   - 敌人立即死亡并移除；
   - 玩家获得反弹速度 `STOMP_BOUNCE`；
   - 加 `STOMP_SCORE` 分。
2. 否则判定为**受伤**（见 5.5）。
3. 踩踏判定优先于受伤判定。

### 5.4 玩家（player.js）

1. 水平移动：按住 ←/→ 移动，速度 `±MOVE_SPEED`；松开即停。
2. 跳跃：仅 `grounded == true` 时，按跳跃键令 `vy = JUMP_VELOCITY`。跳跃为边沿触发（一次按下只触发一次起跳）。
3. 无敌计时：受伤后 `invincible = INVINCIBLE_TIME`，随逻辑帧递减；期间不响应新的受伤判定。
4. 坠落死亡：玩家碰撞盒顶部 `y > 关卡像素高度 + PIT_DEATH_MARGIN` 时判定坠落（由 game 层处理扣命重生）。

### 5.5 敌人（enemy.js）

1. 巡逻：以 `ENEMY_SPEED` 沿当前方向水平移动。
2. 撞墙转身：水平移动碰到固态格子时反向。
3. 边缘转身：当前进方向前方、碰撞盒底边下方一格不是固态格子（即前方是悬崖）时反向，
   避免敌人走出平台坠落。
4. 敌人不受重力影响（巡逻路径视为始终贴地）；敌人与金币、旗帜无交互。

### 5.6 生命与计分（game.js）

1. 初始：生命 3、分数 0、关卡 1。
2. 受伤：非无敌状态侧面碰敌 → 生命 -1，进入 1.5 秒无敌；生命归 0 → **游戏结束（GAME_OVER）**。
3. 坠落：掉落深渊 → 生命 -1；生命归 0 → 游戏结束；否则从**当前关卡起点重生**
   （玩家回到出生点、敌人与金币恢复为关卡初始状态，分数与剩余生命保留）。
4. 计分：金币 +100；踩敌 +100；通关奖励 = 当前剩余生命 × 200（结算后进入下一关）。
5. HUD 显示当前分数与剩余生命（心形图标）。

### 5.7 关卡与流程（level.js / game.js）

1. 关卡数据：ASCII 地图文本定义（见第 7 节），共 3 关，由 `LEVELS` 数组提供。
2. 通关：玩家碰到终点旗帜 → 结算通关奖励分 → 显示「LEVEL CLEAR」画面停留 `LEVEL_CLEAR_PAUSE`：
   - 若为第 1/2 关 → 进入下一关（分数、生命延续，关卡实体重新加载）；
   - 若为第 3 关 → **胜利（VICTORY）**，显示最终总分。
3. 游戏状态机（state）：`TITLE → PLAYING → LEVEL_CLEAR → PLAYING / VICTORY`，以及 `PLAYING → GAME_OVER`。
4. TITLE：任意开始操作（Enter/空格/触屏开始按钮）→ 重置生命/分数 → 第 1 关 → PLAYING。
5. GAME_OVER / VICTORY：按开始操作 → 回到 TITLE。
6. 关卡内时间逻辑（如 LEVEL_CLEAR 停留计时）以逻辑帧 dt 累积推进，保证可测试。

### 5.8 镜头（camera.js）

1. 镜头水平跟随：目标 x = 玩家中心 x − `VIEW_WIDTH / 2`。
2. 边界限制：`x ∈ [0, 关卡像素宽度 − VIEW_WIDTH]`；关卡不高于视口，垂直方向恒为 0。
3. 镜头只影响渲染层平移，不影响任何物理与碰撞逻辑。

## 6. 输入规范（input.js）

### 6.1 键盘

| 按键 | 动作 |
| --- | --- |
| ← / → | 左右移动（按住持续移动） |
| 空格（或 ↑） | 跳跃（边沿触发） |

### 6.2 触屏

1. 仅当设备支持触摸（`ontouchstart` 存在或 `pointer: coarse`）时显示虚拟按钮。
2. 布局：屏幕左下角「◀」「▶」按钮；右下角「跳」按钮。
3. 按钮使用 `pointerdown/pointerup/pointercancel` 事件，支持多点触控（不同手指分别按住不同按钮互不干扰）。
4. 触屏按键语义与键盘完全一致：方向键按住持续移动，跳跃边沿触发。
5. 触屏设备上同样保留键盘输入支持。

### 6.3 输入抽象

`input.js` 向上层暴露稳定接口（供 main.js 使用）：

- `isLeft()` / `isRight()` — 当前是否按住左/右；
- `consumeJump()` — 读取并清除跳跃边沿信号（每个逻辑帧最多触发一次）。

## 7. 关卡数据格式（level.js）

### 7.1 ASCII 地图

- 每关 17 行字符串，每行 100 个字符（不足自动补空格）。
- 字符图例：

| 字符 | 含义 | 备注 |
| --- | --- | --- |
| `#` | 固态格子（地面/平台/墙） | 每关必须存在 |
| `C` | 金币 | 拾取后消失 |
| `E` | 敌人出生点 | 初始朝左巡逻 |
| `P` | 玩家出生点 | 每关恰好 1 个；缺失时默认放在 (32, 0) |
| `F` | 终点旗帜 | 每关恰好 1 个 |
| `.` / 空格 | 空地 | |

- 行顺序：第 0 行为关卡顶部。
- 解析规则：
  - 金币碰撞盒：以格子中心为中心的 24×24 矩形；
  - 敌人碰撞盒：32×32，出生点对齐格子；
  - 玩家出生点：`P` 所在格子的左上角；玩家碰撞盒 28×36；
  - 旗帜：`F` 所在格子整格为触发区域。

### 7.2 关卡设计约束

1. 每关必须包含：至少 1 个玩家出生点、1 个旗帜、若干地面。
2. 底部必须存在地面，深渊区域为地图底部留空的列（玩家掉落即死亡）。
3. 关卡像素宽度 = 100 × 32 = 3200 px，高度 = 17 × 32 = 544 px。
4. 第 1 关难度最低（教学），第 3 关难度最高。
5. 三关金币总数建议分别为约 10 / 14 / 16 个，敌人 2 / 3 / 4 个。

### 7.3 解析结果结构

```js
{
  rows: 17, cols: 100, tileSize: 32,
  widthPx: 3200, heightPx: 544,
  solids: [[bool,...], ...],      // 固态格子二维数组
  coins:    [{ x, y }],           // 金币中心坐标（px）
  enemies:  [{ x, y }],           // 敌人出生点（px，左上角）
  playerSpawn: { x, y },          // 玩家出生点（px，左上角）
  flag: { x, y, w, h }            // 旗帜触发区域
}
```

## 8. 渲染规范（renderer.js，不写测试）

1. Canvas 逻辑分辨率 960×544，通过 CSS 等比缩放适配窗口（保持宽高比）。
2. 天空背景 + 地平线以下填色；镜头平移下绘制可见范围的 Tile。
3. 实体外观（几何占位）：
   - 玩家：红色圆角矩形（无敌闪烁期间按 100 ms 周期显隐）；
   - 敌人：紫色方块；
   - 金币：金色圆形；
   - 旗帜：灰色旗杆 + 红色三角旗。
4. HUD（左上角）：`SCORE: <分数>`；生命以红心 ×N 显示。
5. 覆盖层：TITLE（游戏名 + 开始提示）、LEVEL CLEAR（第 n 关通关）、VICTORY（最终总分）、GAME_OVER。
6. 覆盖层之上仍允许输入（开始/重新开始）。

---

## 9. 游戏循环（main.js）

1. `requestAnimationFrame` 驱动；每帧计算 `elapsed`，累积至逻辑累加器；
2. 逻辑累加器 ≥ `FIXED_DT` 时执行 core 层 `update`，单帧最多追赶 5 个逻辑帧（防螺旋）；
3. 每帧渲染一次。
4. 装配顺序：创建 game → 绑定 input → 每逻辑帧 `game.update(input, FIXED_DT)` → 每渲染帧 `renderer.render(game, camera)`。

## 10. 验收标准

1. `npm install` 后 `npm run test` 全部测试通过（测试与 TEST_CASES.md 用例一一对应）。
2. `npm run dev` 启动后浏览器可玩：桌面键盘 + 手机触屏均可完成第 1 关。
3. 完整通关 3 关后显示 VICTORY 画面与总分；生命耗尽显示 GAME_OVER。
4. 玩家不能穿墙、不能穿地面；顶头会失速；空中不能二段跳。
5. 敌人撞墙/悬崖转身；踩头消灭加分；侧面碰撞扣命并闪烁无敌。
6. 掉落深渊扣命并从当前关卡起点重生，金币敌人复位、分数保留。
7. 镜头始终跟随玩家且不越出关卡边界。
8. 触屏按钮仅在触屏设备显示，多点触控互不干扰。
